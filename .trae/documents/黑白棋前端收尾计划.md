## 一、Summary 概要

完成黑白棋前端，使其与无限制象棋前端**视觉与架构一致**（同一套 Shadow DOM Web Component + 同一套 Playfair Display / DM Sans / JetBrains Mono 字体 + 同一套 paper/ink 极简美学），并适配黑白棋的落子语义（点空格直接落子 + 翻转动画 + 合法落子点指示器）。最后更新 README 并跑通端到端验证。

**关键修正（基于 Phase 1 探索）**：象棋的 `static/style.css` 是**遗留未使用文件**——`xiangqi/static/index.html` 不引用它，全项目 grep `style.css` 零命中。真正的设计完全内嵌在 `app.js` 的 `_getStyles()`（注入 Shadow DOM）+ `_getHtmlTemplate()` 中。已创建的 `heibaiqi/static/index.html` 也只加载字体 + `app.js`。因此**不再创建 `static/style.css`**，所有前端工作集中在 `app.js`。这符合"不创建不必要文件"原则，且"前端与象棋一致"的要求由复刻 `app.js` 内嵌设计来满足。

## 三、Proposed Changes 拟议变更

### 3.1 创建 `/workspace/heibaiqi/static/app.js`（核心）

**What**：`HeibaiqiBoard` Web Component（extends HTMLElement，Shadow DOM），复制自 `xiangqi/static/app.js` 全文后定向改造。

**How（复制 → 改造清单）**：

1. **类与注册**：`XiangqiBoard`→`HeibaiqiBoard`；`customElements.define('xiangqi-board',…)`→`'heibaiqi-board'`；`playerSide` getter 默认 `'red'`→`'black'`。

2. **`_getHtmlTemplate()` 文案**：
   - `<h1>无限制象棋</h1>`→`<h1>无限制黑白棋</h1>`
   - `#turn-indicator` 默认 `红方回合`→`黑方回合`
   - `.hints` 示例改为黑白棋场景：`"把棋盘改成10×10"、"让AI接管白棋"、"创建一个能跳吃的棋子"、"悔一步棋"`
   - 难度 `<select>` 选项对齐 `rules.json`：`easy/normal/hard/master`（象棋是 easy/medium/hard）
   - `placeholder` 改为黑白棋语境

3. **`_getStyles()` 改造**：
   - `--board-bg: #f0d9b5`→`#1a5d3a`（经典 Othello 绿，与 `ui_config.json` 一致）
   - `--board-line`→`#000000`
   - `#board-container`：`height: calc(min(90vmin,600px)*10/9)`→`height: min(90vmin,600px)`（1:1 正方形）
   - `.header h1::before { content:'象 棋' }`→`content:'黑 白 棋'`
   - `.piece`：保留定位/圆形；新增 `.piece.black`（`background:var(--ink);border:2px solid var(--ink)`）、`.piece.white`（`background:var(--paper);border:2px solid var(--ink)`）；移除依赖 `.piece-text` 文字的尺寸（disc 无文字，按比例缩放为单元格 ~80% 直径）
   - 删除 `.river-text`、`.piece.red`、九宫相关（如有）
   - **新增翻转动画**：
     ```css
     @keyframes pieceFlip {
       0%   { transform: translate(-50%,-50%) rotateY(0deg); }
       50%  { transform: translate(-50%,-50%) rotateY(90deg); }
       100% { transform: translate(-50%,-50%) rotateY(180deg); }
     }
     .piece.flipping { animation: pieceFlip 0.45s ease-in-out; }
     ```
   - **新增合法落子点指示器** `.valid-placement`（半透明金色圆点，pointer-events:auto，hover 放大），并保留旧 `.valid-move-indicator` 类名以最小改动（复用其定位逻辑，仅样式调整）。

4. **`renderBoard()` 重写**（8×8 单元格网格）：
   - `width=8 height=8`；`river_line=null`；`palace=null`；`orientation='horizontal'`
   - viewBox `0 0 8 8`，`preserveAspectRatio='none'`，svg 宽高 100%
   - 画 9 条竖线（x=0..8，y 0..8）+ 9 条横线（y=0..8，x 0..8），`stroke=lineColor`，`stroke-width` 取 `layoutConfig.grid.line_thickness`（默认 0.03）
   - **不画** river_gap 分段、不画 palace 对角线、不画 river-text
   - 保留 `decorations.border`（边框 rect 0,0,8,8）
   - 背景色取 `layoutConfig.appearance.background_color`（#1a5d3a）
   - 末尾 `this.applyUiConfig()`

5. **`renderPieces()` / `createPieceElement()` 重写**：
   - 不创建 `.piece-text` span（disc 无文字）
   - 定位改**单元格中心**：`leftPct = ((x+0.5)/width)*100`，`topPct = ((y+0.5)/height)*100`
   - 按 `piece.side` 上色：`black`→实心黑圆；`white`→实心白圆带黑边
   - 尺寸：`width/height` 约单元格的 80%（如 `width: 9%; height: 9%`，8×8 下每格 12.5%）
   - `custom_properties.color/bg` 仍支持（AI 可自定义棋子外观）
   - 点击：保留 `coordInsertMode` 分支；其余**不再触发 onPieceClick**（黑白棋点空格落子，点已有棋子无操作）——改为空操作或仅高亮，避免误触

6. **交互层重写（核心差异）**：
   - **删除** `onPieceClick` / `highlightPiece` / `clearSelection` 的选子语义（保留空函数或删除调用点）
   - **新增** `renderValidPlacements()`：`fetch /api/valid_moves {side: boardState.current_turn}` → 在每个合法点渲染 `.valid-placement` 金色圆点（单元格中心定位），点击 → `placeStone(x,y)`
   - **新增** `placeStone(x,y)`：`fetch /api/move {to:[x,y]}` → 成功后：
     1. `this.boardState = data.board_state`
     2. `renderPieces()` + 对 `data.flipped` 中的 id 播放 `pieceFlip` 动画（加 `.flipping` 类，动画结束移除）
     3. `renderValidPlacements()` 刷新
     4. 更新回合指示器；若 `game_status.state==='ended'` 显示结束遮罩
   - **改** `aiMove()`：`fetch /api/ai_move` → 同上渲染（落子 + 翻转动画），用 `data.ai_move.flipped`
   - 棋盘容器点击：当 `coordInsertMode` 关闭时，点击合法落子点（由 `.valid-placement` 自身处理）；点击空格非合法点则忽略
   - `executeMove` 旧函数删除或改为调用 `placeStone`

7. **`init()` 调整**：加载配置后调 `renderBoard()` `renderPieces()` `renderValidPlacements()` `updateTurnIndicator()`；绑定按钮事件保留（undo/restart/reset/undo_config/logs/settings/send）。

8. **文案全局替换**：`象棋`→`黑白棋`、`红方`→`黑方`（按 current_turn 动态显示黑方/白方）、`checkmate` 类判断改 `game_status.state==='ended'` + `winner`。

9. **保留不动**：`sendCommand`、区段替换（SECTION/END）、模态框（settings/logs）、思考遮罩、token 统计渲染、机制列表渲染、性格卡片渲染、coord 选点模式、RPG 相关属性（`rpg-mode`/`api-base`/`player-side`）、所有动画 keyframes（fadeInUp/scaleIn/slideIn/spin）。

**Why**：黑白棋落子语义（点空格 + 翻转）与象棋（选子 + 移动）根本不同，交互层必须重写；但 UI 外壳与设计系统完全复用，保证"前端与象棋一致"。

**验证点**：浏览器加载无 console 报错；8×8 绿盘 + 中心 4 子 + 4 个金色合法点；点击合法点落子并播放翻转动画。

| # | 决策项 | 选择 | 理由 |

| D1 | `static/style.css` | **不创建** | Phase 1 证实象棋/黑白棋均不加载它，属遗留文件；设计在 app.js 内嵌 |
