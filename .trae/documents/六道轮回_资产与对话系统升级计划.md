# 六道轮回 · 资产与对话系统升级计划

## 摘要

本计划针对「六道轮回」棋+RPG 游戏执行 6 项资产与前端升级：
1. 用 **rembg ML 语义分割**重新抠图全部 13 个角色立绘，替换原有颜色距离算法 PNG
2. 改造类 Galgame 对话框：人物对齐画面下边沿，对话框 **75% 透明度**覆盖人物下半身
3. 在 `shared/assets/audio/bgm/` 列出 8 首 BGM 清单（含主题与风格）
4. 用内置 AI 生图生成 6 类像素画 UI 资源（法轮/六道图标/3种粒子/立绘边框）
5. 用 AI 生图统一**陈默**形象（可爱+温和并存），替换 7 张立绘 + flipper_as_chenmo + cg_memory_hungry，共 9 张
6. 为**林夜 + 陈默**关键表情生成 6 帧 AI 关键帧，JS 在 12FPS 循环播放（CSS 无真插值，采用逐帧 + CSS 过渡）

- **角色立绘**：`shared/assets/characters/{13个文件夹}/*.jpg`（带暗色背景）+ `*.png`（由 `cutout_all.py` 用颜色距离+连通域算法抠图，可能残留光晕、头发边缘差）
- **对话系统**：`hub/dialogue.html`（CSS）+ `hub/dialogue.js`（打字机、立绘切换、选择、低语）
  - 立绘 `.character-portrait`：78vh，`object-position: bottom center`，`align-items: flex-end`（已对齐底部）
  - 对话框 `.dialogue-box`：`z-index:2`（在立绘 z-index:1 之上），`margin: 0 40px 20px`，`background: rgba(20,20,30,0.85)`（85% 不透明）
  - `dialogue.js` 的 `updatePortraits()` 优先加载 PNG，回退 JPG；同一时刻仅显示 1 个立绘
- **音频**：`shared/assets/audio/sfx/*.wav`（27 个音效）；**bgm/ 目录不存在**，8 首 BGM 在设计书中指定但未提供
- **UI**：`shared/assets/ui/` 目录不存在；UI 由内联 CSS/SVG 实现
- **资产生成脚本**：`shared/assets/generate_all.py`（仅生成 boy/robot，用 ARK Seedream API）、`cutout_all.py`

### 不存在/缺口
- `shared/assets/audio/bgm/` 目录与 8 首 MP3
- `shared/assets/ui/` 目录与像素画 UI 资产
- 陈默形象跨图一致性（当前各图可能风格不统一）
- 立绘逐帧动画运行时（dialogue.js 无帧循环逻辑）

## 实施步骤

### 步骤 1：rembg ML 抠图升级

**文件变更：**
- 新建 `shared/assets/cutout_rembg.py`：用 rembg Python API 批量处理 `characters/*/*.jpg` → 覆盖同名 `.png`（RGBA）
  - 算法：`from rembg import remove; remove(Image.open(src))` → 保留半身像，透明背景
  - 对像素画友好的轻度 alpha 羽化（保留 RGB 锐利）
  - 失败回退到现有 cutout_all.py 的颜色距离算法
- 修改 `requirements.txt`：添加 `rembg`（及隐式依赖 onnxruntime）
- 保留原 `cutout_all.py` 不动（作为回退）

**执行：**
- `pip install rembg`
- `python shared/assets/cutout_rembg.py`（首次运行下载模型 ~170MB，需网络）

**验证：** 检查每个角色文件夹 PNG 已更新，背景为透明（可用 PIL 抽样 alpha 角落=0）

---

### 步骤 2：对话框改造（人物下沿对齐 + 75% 透明）

**文件变更：** `/workspace/hub/dialogue.html`（内联 `<style>`）

**修改点：**
1. `.dialogue-box` 的 `background`：
   - `rgba(20, 20, 30, 0.85)` → `rgba(20, 20, 30, 0.25)`（**75% 透明度** = 25% 不透明）
   - 保留 `backdrop-filter: blur(8px)` 维持文字可读性（轻微模糊）
   - `border` 改为 `1px solid rgba(212,175,55,0.35)`（金边略加重以补偿透明）
2. `.dialogue-box` 的 `margin`：
   - `margin: 0 40px 20px` → `margin: 0 40px 0`（**紧贴画面下边沿**，盖住立绘下半身）
3. `.dialogue-box` 的 `min-height`：
   - `160px` → `200px`（确保盖住半身像腰部以下，对话框成为视觉前景）
4. `.character-portrait`：
   - 已是 `align-items: flex-end` + `object-position: bottom center`，无需改
   - 调整 `height: 78vh` → `82vh`（让人物更大、更贴近底部，被对话框盖住下半部）
   - 保留 `drop-shadow` 与 `.speaking` 金色发光
5. z-index 关系不变（对话框 z-index:2 在立绘 z-index:1 之上 → 对话框盖住立绘下半身，但因 75% 透明可透出人物）

**验证：** 启动 hub，进入对话页，确认：人物底部被半透明对话框覆盖、文字清晰、人物上半身可见

## 假设与约束

1. **rembg 模型下载**：首次运行需联网下载 ~170MB onnx 模型；沙箱有网络则可行，否则回退到优化版颜色距离算法
2. **AI 生图一致性**：陈默跨图一致性靠**固定 CANON 提示词**保证（无 reference image 锁定能力，靠文本一致性最大化）
3. **动画帧一致性**：6 帧间角色形象靠提示词固定 + 明确帧序描述；CSS 无真插值，靠逐帧 83ms 切换 + 浏览器像素渲染实现视觉流畅
4. **陈默性格基调**：保持"温和"内核但增加"可爱"外观（更柔和的五官/发饰），不改变剧情文本
5. **不改动**：`story.json` 剧情、后端 `story_api.py`、其他角色立绘、音效系统
6. **不创建**额外文档（BGM清单除外，因用户明确要求）
