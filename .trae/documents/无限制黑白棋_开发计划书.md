# 无限制黑白棋（Unlimited Reversi）开发计划书

> **版本**: v1.0
> **创建日期**: 2026-07-22
> **基础**: 借鉴 `/workspace/xiangqi/` 无限制象棋 v4.1 架构
> **设计哲学**: 灵活编码（最高纲领）— 一切新功能由 AI 编码实现，不可硬编码

---

## 一、Summary 概要

在 `/workspace/heibaiqi/` 新建黑白棋（Reversi/Othello）游戏，复刻无限制象棋的二级 AI 协作流水线 + JSON Patch 优先策略 + 机制引擎 + AI 性格系统。核心创新点：在 `jump`/`ray` 双原子原语之外，**新增 `flip` 第三原语**，将"落子翻转夹吃"表达为一等公民的可编码原语，符合"灵活编码"宗旨。

**关键产出**：
- 8×8 标准黑白棋盘 + 初始 4 子（中心交叉）
- black/white 双阵营，单一 `disc` 棋子类型
- `flip` 原语 + 沿用 `where` 条件表达式引擎
- AI 自由修改棋盘/规则/UI/机制/创建棋子/性格
- 前端保持象棋极简水墨风格（Noto Serif SC + 纯黑白调色板）
- 端口 **8003**，由 `/workspace/main.py` 统一启动

#### 3.2.2 `heibaiqi/rule_engine.py`（复制自 `xiangqi/rule_engine.py`）

**What**: 规则引擎，承载 `jump`/`ray`/`flip` 三原语 + `where` 条件引擎

**关键修改**：
- **新增 `flip` 原语执行**：
  - `kind: "flip"` + `dir: [dx, dy]` + `max: N`（最大翻转距离，默认 6）+ `land: "enemy"`（沿方向遇到的第一颗己方棋子之前的所有敌方棋子被翻转）+ `sym`（对称展开）
  - 语义：从落子点出发沿 `dir` 方向，必须先经过 ≥1 颗敌方棋子，再遇到一颗己方棋子，中间所有敌方棋子翻转阵营
  - `_flip_moves(piece, board_state)`：返回该 disc 的合法落子点（必须能翻转至少 1 颗敌方棋子）
- **新增 `get_valid_placements(side, board_state)`**：聚合该方所有 disc 的 `_flip_moves`，去重得到全局合法落子点
- **新增 `apply_flip_captures(pos, side, board_state)`**：实际执行翻转，返回被翻转的棋子 id 列表
- **删除象棋特有方法**：`_in_palace`、`_crossed_river`、`_is_own_side`、`is_in_check`、`is_checkmate`、`is_general_captured`、飞将逻辑、`_king_types`
- **保留**：`get_valid_moves`（兼容自定义棋子的 jump/ray）、`_get_move_definitions`、`_expand_symmetry`、`_execute_move_def`、`_jump_moves`、`_jump_region_moves`、`_ray_moves`、`_eval_where`、`_eval_condition`（in_region/crossed_river/same_side/at_row/at_col/not/and/or 全部保留，AI 可自由用于自定义棋子）
- **新增游戏结束判断**：`is_game_over(board_state)` → 双方均无合法落子或棋盘满
- **新增胜负判断**：`get_winner(board_state)` → 棋子数多者胜，相等为平局

**Why**: 黑白棋的"夹吃翻转"是核心机制，必须作为一等原语表达，符合"灵活编码"宗旨；删除象棋特有逻辑避免误导 AI

**How**: 复制 → 删除象棋特有方法 → 新增 flip 三件套（`_flip_moves`/`get_valid_placements`/`apply_flip_captures`）+ `is_game_over`/`get_winner`

**关键修改**：

  - 棋子数差（当前方 - 对方）
  - **角点权重表**（经典 Othello 8×8 权重矩阵）：
    ```
    [120, -20,  20,   5,   5,  20, -20, 120],
    [-20, -40,  -5,  -5,  -5,  -5, -40, -20],
    [ 20,  -5,  15,   3,   3,  15,  -5,  20],
    [  5,  -5,   3,   3,   3,   3,  -5,   5],
    [  5,  -5,   3,   3,   3,   3,  -5,   5],
    [ 20,  -5,  15,   3,   3,  15,  -5,  20],
    [-20, -40,  -5,  -5,  -5,  -5, -40, -20],
    [120, -20,  20,   5,   5,  20, -20, 120]
    ```
  - **行动力**（mobility）：当前方合法落子数 - 对方合法落子数（权重高）
  - **边缘控制**：占边奖励
  - **稳定性**（简化版）：已无法被翻转的棋子奖励
- **重写 `_generate_all_moves`**：调用 `rule_engine.get_valid_placements(side)`，返回 `[(pos, side), ...]`
- **重写 `_simulate_move`**：落子 + 翻转（深拷贝 board_state.pieces，修改被翻转棋子的 side）
- **重写 `_move_score`**：基于位置权重表
- **性格影响**（保留 4 预设）：
  - normal：均衡
  - aggressive：行动力权重 ×2，鼓励激进夹吃
  - defensive：稳定性权重 ×2，鼓励保守占角
  - random：随机化评估 ±30%
  - custom：按 aggressiveness/conservatism/value_biases 参数
- **删除** `_evaluate_custom_piece_value` / `_heuristic_custom_piece_value` / `precompute_custom_piece_values`（黑白棋标准 disc 无价值差异；若 AI 创建自定义棋子，使用启发式默认值 100）
- **新增** `_get_corner_weight(pos)` / `_get_stable_discs(board_state, side)`

**Why**: 黑白棋评估逻辑与象棋完全不同，需基于 Othello 经典理论

**How**: 复制 → 改类名 → 删除 PIECE_VALUES → 重写 `_evaluate`/`_generate_all_moves`/`_simulate_move`/`_move_score` → 新增角点/稳定性辅助方法

- 性格卡片渲染：`renderPersonality()`

## 四、Assumptions & Decisions 假设与决策

### 4.1 关键决策

| # | 决策项 | 选择 | 理由 |
|---|---|---|---|
| 1 | 文件夹命名 | `heibaiqi/` | 遵循项目拼音命名约定（xiangqi/wuziqi/go） |
| 2 | 阵营命名 | `black` / `white` | 黑白棋语义清晰，避免 wuziqi 的 red/white 命名遗留混乱 |
| 3 | 文件命名 | `pieces_black.json` / `pieces_white.json` | 语义明确，符合阵营命名 |
| 4 | **翻转原语设计** | **新增 `flip` 第三原语** | 符合"灵活编码"宗旨，与 jump/ray 并列为一等公民；语义清晰，AI 易理解 |
| 5 | 棋盘尺寸 | 8×8 标准 | 黑白棋标准规格；AI 可自由修改 board.json.geometry |
| 6 | 端口 | 8003 | 紧接围棋 8002 |
| 7 | 棋子类型 | 单一 `disc` | 标准黑白棋仅一种棋子；AI 可通过 PIECE_CREATOR 创建自定义棋子 |
| 8 | 棋子 label | `●` / `○` | Unicode 实心/空心圆，视觉清晰 |
| 9 | 初始布局 | (3,3)白 (4,3)黑 (3,4)黑 (4,4)白 | 标准 Othello 初始 4 子交叉布局 |
| 10 | 胜利条件 | `most_discs` + `no_valid_moves_both` + `board_full` | 黑白棋标准规则 |
| 11 | 先手方 | black | 黑白棋黑先 |
| 12 | 翻转实现 | 修改棋子 `side` 字段 | 翻转后棋子仍在原位，仅阵营改变，符合黑白棋语义 |
| 13 | AI 评估 | 角点权重表 + 行动力 + 棋子数差 + 稳定性 | Othello 经典评估函数 |
| 14 | 棋盘背景色 | `#1a5d3a` 经典绿 | Othello 视觉传统；AI 可通过 UI_MODIFIER 自由修改 |
| 15 | 前端风格 | 极简水墨（与象棋一致） | 用户明确要求；保留 Noto Serif SC + 纯黑白调色板 |
| 16 | chess_ai.py 文件名 | 保留（类名改 OthelloAI） | 最小化 main.py 引用改动 |
| 17 | 无合法落子处理 | 跳过该方回合（special_rules.pass_when_no_move） | 黑白棋标准规则 |
| 18 | flip 原语 max 默认值 | 6 | 8×8 棋盘最大翻转距离为 6（中心到边缘） |
| 19 | flip 原语 sym 默认值 | `rotate4_mirror` | 八方向对称展开，一个 dir 生成 8 方向 |
| 20 | Schema 向后兼容 | pieces.schema.json 扩展枚举值 | 不破坏象棋/五子棋/围棋现有配置 |

### 4.2 假设

1. **DeepSeek API 可用**：沿用象棋的 `api密钥.txt` 机制（`/workspace/api密钥.txt` 或 `/workspace/heibaiqi/api密钥.txt`）
2. **shared/ 目录在 PYTHONPATH 中**：由 `/workspace/main.py` 注入 `WORKSPACE_ROOT`，heibaiqi 可直接 `from shared.schema_validator import ...`
3. **前端字体可从 Google Fonts 加载**：与象棋一致
4. **浏览器支持 Web Components + Shadow DOM**：与象棋一致
5. **jsonschema 库已安装**：与象棋一致

### 4.3 风险与缓解

| 风险 | 缓解 |
|---|---|
| flip 原语 AI 理解偏差 | PIECE_PRIMITIVE_PRIMER 提供 8 个示例 + 语义详解；PIECE_CREATOR 示例覆盖 flip |
| 翻转动画性能 | 一次翻转最多 19 颗，CSS 动画可承受 |
| Schema 枚举扩展破坏象棋 | 仅新增枚举值，不修改现有约束；象棋配置仍通过校验 |
| AI 评估深度过高导致卡顿 | ai_difficulty.levels 限制 depth 1/3/5/7；性格 random 降低搜索质量 |

- 本计划严格遵循"灵活编码"最高纲领：所有黑白棋特有逻辑（翻转、合法点判定、胜负判定）均通过 `flip` 原语 + `where` 条件引擎表达，可被 AI 自由修改
- `flip` 原语的设计是本计划的核心创新点，使黑白棋的"夹吃翻转"机制成为一等公民的可编码原语，与象棋的 jump/ray 形成完整的三原语体系
- 前端使用 frontend-design 技能确保设计质量，同时保持与象棋的视觉一致性（极简水墨风）
