# 六道轮回进度状态机与多结局判定

## 摘要

本分册记录「棋圣·六道轮回」项目中 Roguelike 进度层的核心设计：以六道（地狱 / 饿鬼 / 畜生 / 人 / 阿修罗 / 天）为章节的进度状态机、关卡级业力溢出叠加机制、被天道识破后的锁死处理、沙盒解锁条件，以及由悟道值（e）与堕落值（c）双轴驱动的五级结局判定。所有断言均指向 `文件:行号` 或代码原文；复核中发现的、与立项简报及设计书不符之处，在对应小节与第 6 节如实列出。

## 1 背景与问题定义

项目在六个棋种（xiangqi / weiqi / wuziqi / dongwuqi / tiaoqi / heibaiqi）之上套用一层 Roguelike 剧情结构。玩家沿六道逐道通关，每道由 5 至 6 个预制关卡组成，最后一关为守道者 Boss。玩家的核心行为是「用自然语言向大语言模型发出作弊指令，实时改写棋盘 / 棋子 / 规则 / 机制」，作弊累积业力（业障），业力超阈会非线性推高被天道识破的概率。

进度层要解决三个问题：

1. 多章节（六道）之间的推进与回退，需要一套状态机描述「某道通关后跳几道、到天道后如何终结」。
2. 关卡级的业力需要在「道内跨关叠加、换道清零」，且胜负都要计入，否则后期不可玩。
3. 被识破后不能简单重置进度，需要保留永久进度、锁死识破概率、并把玩家导向终局天道 Boss 战；终局又需根据玩家整局的悟道 / 堕落倾向给出不同结局。

权威事实来源：`REALMS` 常量定义于 `samsara/state.py:12`；每道关卡数定义于 `samsara/progression.py:87-96`（`_get_realm_level_count`）；整体设计见于《六道轮回·整体设计书 v3.1》（`六道轮回_整体设计书_v3.1.md`）。

## 2 相关做法与本方案的区别

业界 Roguelike 进度常见做法是用单一「关卡序号 + 章节序号」的线性状态机，且被「死亡」惩罚通常直接重置当前章节或全部进度。本项目的区别点有三：

- 升道不是固定 +1，而是按「本道是否发生透支」决定跳 1 道或跳 2 道（`samsara/progression.py:47-76` 的 `advance_realm`），透支本身成为一种影响结构进度的惩罚。
- 业力是跨关叠加的「道内累计量」，而非单关临时量；溢出量在关卡结束时计算并写入 `realm_overshoot_carryover`，下一关开始时并入（`samsara/state.py:220-247`）。该叠加对胜负都生效，仅在换道或识破时清零。
- 被识破不重置，而是「锁死」：识破概率锁为 0、保留全部永久进度，通关六道后强制触发天道 Boss 战，再据 Boss 战结果与玩家是否曾「真心祈求」决定结局分支（`samsara/state.py:518-530`，`samsara/endings.py:99-225`）。

## 3 技术方案

### 3.1 数据结构

六道顺序由常量表达，索引即道序：

```python
# samsara/state.py:12
REALMS = ["hell", "hungry", "animal", "human", "asura", "heaven"]
```

进度状态集中在 `SamsaraState._data` 的若干字段：

- `current_realm` / `current_level`：当前道与道内关卡序号。
- `realm_progress`：每道的 `{completed, levels_passed, no_cheat_full_clear}`。
- `realm_overshoot_carryover`：本道上一局业力溢出量，下一关开始时并入。
- `level_karma`：当前关卡的业力值。
- `karma_max`：业力安全阈值（默认 120）。
- `realm_detections`：按道累积的识破概率，键为 `REALMS`。
- `detection_state`：`{is_detected, detection_locked, trigger_boss_on_complete, exposure_path_triggered}`。
- `prayer_count`：真心祈求次数（即玩家使用 AI 修改规则的次数）。
- `alignment`：`{enlightenment, corruption, rationality, emotion}`，其中 `enlightenment`（e）与 `corruption`（c）驱动结局判定。
- `endings_unlocked`、`tiandao_boss_state`、`memory_fragments_unlocked`：结局、天道 Boss、记忆碎片状态。

### 3.2 业力溢出叠加算法

关卡开始（`samsara/state.py:220-234` `reset_level_state`）：

```
base = max(0, initial_karma − initial_karma_reduction)   # initial_karma 默认 50
level_karma = base + realm_overshoot_carryover
```

关卡结束（`samsara/state.py:236-247` `record_level_end`），胜负都执行：

```
threshold = karma_max + karma_max_bonus
overshoot = max(0, level_karma − threshold)
realm_overshoot_carryover = overshoot      # 写入本道，下一关并入
```

换道（`samsara/state.py:258-263` `set_realm`）与识破（`reset_on_detection`）会把 `realm_overshoot_carryover` 清零，实现「换道不携带业力溢出」。

### 3.3 升道状态机

`advance_realm`（`samsara/progression.py:47-76`）的状态迁移如下：

```
                  levels_passed < total_levels
                 ┌──────────────────────────────────┐
                 ▼                                  │
        [停留当前道] ────────────────────────────────┘
                 │ levels_passed >= total_levels
                 ▼
        mark_realm_completed(current_realm)
                 │
          current_index < 5 (未到天道)
                 ├─ overdraft_count == 0 ─► up_2：new = min(index+2, 5)；set_realm + reset_level_state
                 └─ overdraft_count  >  0 ─► up_1：new = index+1；set_realm + reset_level_state
                 │
          current_index == 5 (已在天道)
                 └─► transcend：advanced=True, new_realm="heaven"
```

`retreat_realm`（`samsara/progression.py:78-85`）在 `current_index > 0` 时降 1 道并重置关内状态，否则为空操作。

注意：`mark_realm_completed` 与 `unlock_sandbox` 的实际触发点在 `resolve_level`（`samsara/progression.py:41-44`），即当某道 `levels_passed >= total_levels` 时于关卡结算里执行；`advance_realm` 内部又会再调用一次 `mark_realm_completed`（幂等），但 `unlock_sandbox` 仅出现在 `resolve_level`。

### 3.4 技能点结算

`resolve_level`（`samsara/progression.py:8-45`）在胜利时累加技能点：基础 +1；无作弊（`no_cheat`）再 +2；未透支（即 `overdraft_count == 0`）再 +1；首次击败本道 Boss 再 +1。沙盒模式胜利仅 +1（`samsara/progression.py:16-20`）。失败时不发技能点，但仍会计算并写入业力溢出量。

### 3.5 被识破的锁死处理

`reset_on_detection`（`samsara/state.py:518-530`）不重置进度，只做：

- `detection_state = {is_detected: True, detection_locked: True, trigger_boss_on_complete: True, exposure_path_triggered: True}`
- 对所有道 `realm_detections[r] = 0.0`（识破概率锁死为 0）

此后玩家继续通关六道，全部完成后由 `trigger_boss_on_complete` 触发天道 Boss 战；Boss 战胜且 `prayer_count >= 1` 时命中「识破」结局。

### 3.6 沙盒解锁

某道 `levels_passed >= total_levels` 时，`resolve_level` 调用 `unlock_sandbox(realm)`（`samsara/state.py:492-495`，向 `sandbox_unlocked` 列表追加）。`load_sandbox`（`samsara/levels.py:60-79`）返回沙盒配置，`turn_limit` 取 40（仅当 `game_type == "weiqi"`），其余棋种取 20。

### 3.7 五级结局判定

判定入口为 `determine_ending`（`samsara/endings.py:168-225`），按以下优先级依次短路匹配，先匹配先命中：

| 优先级 | 结局 id | 判定条件（代码原文，见 `samsara/endings.py:99-166`） |
|---|---|---|
| 1 | `exposed`（识破） | `prayer_count >= 1` 且 `exposure_path_triggered` 且天道 Boss `defeated`（`check_exposed_ending`，99-107 行） |
| 2 | `true_me`（真我） | `prayer_count == 0` 且 `all_memory_fragments_collected()` 且 `enlightenment >= 9` 且（未给最终选择或选择为 `"enlightenment"`）（`check_true_me_ending`，109-120 行） |
| 3 | `enlightenment`（悟道） | `prayer_count == 0` 且 `e − c >= 3` 且 `karma < 100` 且（未给最终选择或选择为 `"enlightenment"`）（`check_enlightenment_ending`，122-135 行） |
| 4 | `corruption`（堕落） | `prayer_count == 0` 且 `c − e >= 3` 且 `karma > 200` 且（未给最终选择或选择为 `"corruption"`）（`check_corruption_ending`，137-150 行） |
| 5 | `samsara`（轮回） | `prayer_count == 0` 且 `|e − c| < 3` 且 `100 <= karma <= 200` 且（未给最终选择或选择为 `"samsara"`）（`check_samsara_ending`，152-166 行） |

其中 `e = alignment.enlightenment`，`c = alignment.corruption`，`karma = get_karma()`（当前 `level_karma`）。

若未提供 `final_choice`，上述各 `check_*` 中对 `final_choice` 的约束自动跳过（`if final_choice and final_choice != "..."` 结构），仅靠 alignment 与 karma 维度判定。当所有分支均未命中、`_check_*` 也无法直接判定时，`determine_ending` 还有一段兜底逻辑（227-260 行）：有祈求但未击败天道 Boss 则不允许结束；否则按 `e > c` 取悟道、`c > e` 取堕落、相等取轮回。

## 4 本项目实现

下列实现点均有对应源码：

- 六道常量与顺序：`samsara/state.py:12`。
- 每道关卡数：hell 5 / hungry 5 / animal 5 / human 6 / asura 6 / heaven 6，见 `samsara/progression.py:87-96`。合计 33 关。
- 关卡数据驱动：每道配置由 `configs/level_pools.json` 的 pool 提供，关卡形如 `{"id":"human_1","type":"standard","difficulty":1,"ai_depth":2,"turn_limit":20,"objective":{"type":"checkmate"},"boss_id":...}`；目标类型共 11 种，列于 `configs/objective_types.json`（checkmate / capture_count / turn_limit / evacuation / board_coverage / formation / color_coverage / survival / assassination / escort / compound）。33 关完整内容见顶层 `关卡内容报告书.md`。
- 关卡开始业力：`samsara/state.py:220-234`。
- 关卡结束溢出：`samsara/state.py:236-247`，「胜负都叠加」由该函数在胜利 / 失败分支之外统一执行保证。
- 换道清零：`samsara/state.py:258-263`。
- 升道状态机：`samsara/progression.py:47-76`；回退 `samsara/progression.py:78-85`。
- 技能点结算：`samsara/progression.py:8-45`。
- 被识破锁死：`samsara/state.py:518-530`。
- 沙盒解锁与加载：`samsara/state.py:492-495`、`samsara/progression.py:41-44`、`samsara/levels.py:60-79`；围棋 40 / 其余 20 回合的 `turn_limit` 亦见 `samsara/api.py:211,222,247,364`。
- 五级结局：`samsara/endings.py:99-225`，优先级与判定条件以 3.7 节为准。

## 5 验证情况

本分册所述行为均来自对源码的直接阅读与逐项核对（行号见第 4 节）。以下为针对性的静态核对结论：

- 每道关卡数与 `configs/level_pools.json` 实际关卡数一致（以 hell 为例，pool 含 5 关；`samsara/levels.py:84-88` 的 `get_total_levels` 返回的就是 pool 内关卡列表长度）。
- `advance_realm` 的 `up_2` 上限保护 `min(current_index + 2, len(REALMS) - 1)` 保证不会越过天道索引 5。
- 五级结局的优先级顺序与《设计书》1.x 所述一致，且代码以短路 if 顺序实现，先匹配先返回。

运行时端到端验证（真实对局跑通六道并最终触发某一结局）在本次撰写中未执行，记为「未验证」。

## 6 局限性

- 被识破后 `level_karma` 并未清零。立项简报与设计书 v3.1 第 1.2 / 1.4 / 3.5.4 节均写「业力锁死为 0」，但 `reset_on_detection`（`samsara/state.py:518-530`）实际只锁死 `realm_detections` 与 `detection_state`，并未对 `level_karma` 赋 0。这是设计书与实现的偏差，以代码为准。
- 立项简报对五级结局的简写省略了两个前置条件：结局 2–5 的判定函数均要求 `prayer_count == 0`（一旦祈求过，仅能走 `exposed` 分支），且多数要求 `final_choice` 与结局方向一致（未给选择时该约束自动跳过）。第 3.7 节已按代码补全，与简报的「先匹配先命中」优先级一致，但条件更严格。
- `mark_realm_completed` 在 `resolve_level` 与 `advance_realm` 两处都会被调用，属冗余调用（幂等，不影响正确性）。
- 关卡开始公式中 `initial_karma` 默认 50 由 `_init_defaults`（`samsara/state.py:85`）给出，历史上曾出现 80 / 150 等取值，经版本迁移统一为 50（`samsara/state.py:163-169`），旧存档的迁移行为不在本分册验证范围内。
- 33 关具体配置与 11 种目标类型的语义细节见 `关卡内容报告书.md` 与 `configs/objective_types.json`，本分册只引用其存在与计数。
