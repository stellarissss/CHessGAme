# 棋圣 ChessSage · 游戏爆款化与玩法深化设计

> 借鉴爆款游戏与游戏设计理论，为"利用 AI 大模型作弊"的棋圣平台，思考"如何把这个游戏做好 / 做火"。
> 方法：发散 8 个差异化创意 → 收敛 3 个方向各 1 个可落地详细设计 → 对比优劣 → 确定三阶段递进最终方案。
> 约束：本设计聚焦创意与可行性，不含实现代码；全程遵循项目"灵活编码"最高纲领。

---

## 一、项目现状与设计起点

### 1.1 核心身份
- **棋圣 ChessSage · "六道众生"**：6 种棋类总坛，由 [main.py](file:///workspace/main.py) 统一拉起。
- 六界映射（[main.py](file:///workspace/main.py)）：象棋=人界、五子棋=天界、围棋=阿修罗、动物棋=畜生界、跳棋=饿鬼界、黑白棋=地狱界。
- **核心玩法**："利用 AI 大模型作弊"——玩家用自然语言实时改写规则 / 棋盘 / 棋子 / 界面（见 [README.md](file:///workspace/README.md)）。

### 1.2 灵活编码（最高纲领）
- 详见 [无限制象棋_完整计划书_v4.0.md](file:///workspace/xiangqi/无限制象棋_完整计划书_v4.0.md)：除已硬编码部分外，所有新功能皆不可硬编码，必须用 AI 编码实现；可牺牲稳定性 / token / 速度。
- **已硬编码基础设施**：规则引擎 jump/ray 原子 + where 条件、机制引擎 5 原语、AI 性格应用、JSON Schema 校验、撤销栈、token 统计。
- **AI 驱动内容**：规则 / 棋盘 / 棋子 / 界面修改、自定义棋子、机制组合。
- 本设计的任何新玩法，都须落在"AI 生成内容 + 薄基础设施"这一模式上。

### 1.3 可复用资产（落地的着力点）
| 资产 | 文件 | 对设计的意义 |
|-|-|-|
| 二级 AI 流水线（意图解析→代码生成→JSON Patch→校验） | [ai_orchestrator.py](file:///workspace/xiangqi/ai_orchestrator.py) | 任何"作弊内容"都走这条管线 |
| 指令分类体系 A/B/C/C+/D/E/F | [prompts.py](file:///workspace/xiangqi/prompts.py) | 天然的"作弊严重度 / 业力"信号 |

| AI 性格系统（normal/aggressive/defensive/random/custom + value_biases） | [mechanism_engine.py](file:///workspace/xiangqi/mechanism_engine.py) | AI 跨局记忆 / 养成的现成接口 |
| 成就系统 + 元成就（samsara/collector/completionist/pokedex） | [main.py](file:///workspace/main.py) | 跨局 meta 进度已具雏形 |

| 每局 configs（board/pieces/rules/board_state/ui_config） | 各游戏 `configs/` | 残局 / 契约卡的序列化载体 |

### 1.4 核心风险（设计头号靶点）
**"无限作弊 = 无聊"**：沙盒一旦没有循环与张力，新鲜感退潮后留存崩塌。本设计的根本目标是给"灵活编码"套上一个有张力的循环。

## 二、发散阶段：8 个差异化创意

> 借鉴对象：Balatro / Slay the Spire / Inscryption / BABA IS YOU / Wordle / Mario Maker / Outer Wilds / Vampire Survivors / 德扑 / Tamagotchi / Dwarf Fortress。
> 理论：MDA、Flow、Roguelike 循环、魔法圈（cheating 游戏天然颠覆魔法圈）、知识型进度。

1. **"作弊契约" Roguelike 模式**（Balatro/StS）：每局持有限"作弊预算"，从随机"作弊卡"选改规则，AI 同时抽"反作弊卡"。把灵活编码做成可重玩循环。
2. **"规则乱斗" 异步残局分享**（Mario Maker）：玩家造作弊残局生成挑战码，好友用最少 token / 步数破解，UGC + 排行榜。
3. **"六道轮回" 业力元叙事**：作弊行为积累业力，业力决定下一世轮回到哪一道，把 6 个孤立沙盒串成救赎 / 堕落故事线。
4. **"AI 性格养成" 宠物化对手**（Tamagotchi/宝可梦）：AI 跨局记忆玩家风格并演化性格，从"工具"变"角色"产生情感羁绊。
5. **"每日作弊挑战" Wordle 式分享**（Wordle）：每日全球同题残局 + 目标，完成后生成 emoji 作弊卡片分享，低门槛病毒增长。
6. **"破规推理" 反向解谜模式**（Obra Dinn/Her Story/BABA IS YOU）：AI 偷改规则，玩家观察异常反向推理被改的规则，把不可预测变解谜。
7. **"作弊经济学" 风险博弈**（Vampire Survivors/德扑）：作弊消耗"灵力 / 业力"，强作弊昂贵、AI 也作弊抢资源，收敛"何时作弊 / 多狠"的张力决策。
8. **"棋谱剧场" 自动叙事生成**（Inscryption/Dwarf Fortress）：局后 AI 把作弊史 + 棋谱转写成"评书" + 可视化回放，让作弊成为创作。

## 三、收敛阶段：3 个方向的详细设计

> 选定对"做好 / 做火"最关键的 3 个方向：**A 可重玩核心循环**（解决好不好玩 / 留不留）、**B 社交 UGC 传播**（解决怎么火）、**C 叙事情感深度**（解决为什么长久玩）。

### 方向 A：可重玩核心循环 ——「作弊契约」Roguelike + 作弊经济学

**问题**：沙盒缺循环 → 无限作弊即无聊。**方案**：把"灵活编码"本身做成 Roguelike 核心循环。

**A1. 契约卡系统（Contract Cards）**
- 各游戏新增 `configs/contracts.json` 定义卡池。每张卡 = `{id, name, rarity, cost, prompt, classification}`。
- `prompt` 是一条自然语言作弊指令（如"让我的马可以跳过任何一格"）；`classification` 标 A/B/C/D 之一。
- **打卡 = 走现有 `/api/command` 管线**：卡只是"预置自然语言 + 成本"，真正的 JSON Patch 仍由 [ai_orchestrator.py](file:///workspace/xiangqi/ai_orchestrator.py) 的意图解析 → 代码生成 → 校验生成。
- 玩家可"自创卡"：输入自定义 prompt → 验证可行 → 存入卡池（UGC 闭环，与方向 B 接轨）。

**A2. 作弊预算（灵力 / Qi）**
- `board_state` 增 `cheat_budget` 字段（基础设施级硬编码，类比已有 `move_history` / `mechanisms`）。
- 获得：吃子、达成里程碑、**克制不作弊 N 回合**（克制奖励，对冲"无限作弊"）。
- 消耗：打契约卡（按 `cost`）、直接发自由指令（按分类计费：B/C 类贵、D 类便宜、E 类免费）。
- 计费复用现有 `classification` 输出 + [token_stats](file:///workspace/xiangqi/configs/token_stats.json) 既有机制。

**A3. Roguelike 关卡结构（六道即生物群系）**
- 一局 run = 串联数个"棋境关卡"，复用六道作为 biome：每关指定游戏 + 初始局面 + AI 难度 + 契约池。
- 通关 → 获灵力 + 从 3 张随机卡中 draft 1 + 解锁新卡（meta 进度接入 [achievements.json](file:///workspace/achievements.json)）。
- 失败 → run 结束，meta 进度保留，跨 run 解锁更稀有卡。
- 难度递增复用 [rules.json](file:///workspace/xiangqi/configs/rules.json) 中 `ai_difficulty` 的 depth/randomness 档位。

**A4. AI 反作弊卡（对称）**
- 玩家打卡后，AI 抽一张反制卡（如玩家"飞马"→AI"绊马索"给马加 block）。反制卡同样走 AI 管线生成 patch。
- 形成自适应难度 + 涌现 combo，破解"AI 永远被动"的乏味。

**A5. 落地触点**
- 新增：各游戏 `configs/contracts.json`、`configs/run_state.json`、`configs/unlocks.json`。
- 改：`board_state.schema.json` 增 `cheat_budget`；[main.py hub](file:///workspace/main.py) 增"契约模式"入口；[ai_orchestrator.py](file:///workspace/xiangqi/ai_orchestrator.py) 增 `apply_contract_card(card_id)` 复用 `process_command`；[achievements](file:///workspace/main.py) 增 run 里程碑。

**灵活编码合规**：卡牌内容（prompt / classification）是数据；效果由 AI 现场编码生成 patch；仅 `cheat_budget` 计数器与 run 状态机为薄基础设施硬编码——与现有"机制原语硬编码 + 组合 AI 驱动"模式一致。

### 方向 B：社交与 UGC 传播 ——「每日作弊挑战」+「棋谱剧场」+「残局分享」

**问题**：缺传播入口与新鲜感。**方案**：Wordle 式每日挑战为锋利楔子，棋谱剧场做情感二次传播，残局分享做 UGC 生态。

**B1. 每日作弊挑战（Daily Cheat Challenge）**
- 每日由 AI 以日期为种子生成一道固定题：`daily_challenge.json` = `{date, game, initial_board_state, objective, par_tokens, par_moves}`。
- 目标示例："3 步内、用 1 条作弊指令将死黑方"。生成复用 [ai_orchestrator](file:///workspace/xiangqi/ai_orchestrator.py) 的意图 + 代码 AI。
- 求解：加载题目 → 限制 ≤N 条指令、≤M 步 → 现有 `/api/command` + `/api/move` 执行 → 新增 wrapper 校验目标 + 计分 `score=f(tokens,moves,time)`。
- **可分享作弊卡片**（Wordle 式）：求解后生成 emoji 网格——指令类型行（🅰️机制/🅱️棋盘/🅲规则/🅳界面）、逐步成败（🟩🟦⬜）、token 档（🪙）、结果（🏆），纯前端字符串一键复制；hub 提供"分享"按钮。

**B2. 棋谱剧场（Replay Theatre）**
- 任意一局结束后（非仅每日），AI 基于 `move_history` + [ConversationLog](file:///workspace/xiangqi/ai_orchestrator.py) 生成"评书 / 小说"叙事段（"红马化作飞马跨楚河，黑将仓皇…"）。
- 配可拖拽回放（回放 = board_state 快照序列，move_history 已具备）。
- 局终"剧场"按钮 → 叙事 + 回放 + 作弊时间线。

**B3. UGC 残局分享（造局者模式）**
- 玩家摆初始局面 + 用自然语言写目标 → AI 校验可解性 → 生成分享码（base64 of board_state + rules + goal）→ 好友经 `/api/load_challenge?code=` 加载挑战。
- 复用各游戏现有 config 加载基础设施。

**B4. 落地触点**
- [main.py hub](file:///workspace/main.py) 新增 `/api/daily`、`/api/daily/submit`、`/api/daily/leaderboard`、`/api/theatre`、`/api/load_challenge`；新增 hub 页 `daily.html`、`theatre.js`。
- 新增：`daily_challenges/` 目录、`daily_leaderboard.json`。
- [ai_orchestrator.py](file:///workspace/xiangqi/ai_orchestrator.py) 增 `generate_daily_challenge(seed)`、`generate_replay_narrative(history)`。
- 各游戏前端 `app.js` 增分享卡生成（或抽到 [shared/](file:///workspace/shared)）。

**灵活编码合规**：每日题 / 残局目标 / 评书叙事全部由 AI 生成；分享码仅是已有 config 的序列化；只有计分 wrapper 与 leaderboard 存储为薄基础设施硬编码。

### 方向 C：叙事情感深度 ——「六道轮回业力」+「AI 跨局记忆」

**问题**：六道众生主题目前是空壳 UI；无长期牵挂。**方案**：把主题兑现成叙事灵魂 + 把 AI 变成有记忆的角色。

**C1. 业力值（Karma）**
- 跨 run / 跨游戏持久值，存 `karma.json`（或扩展 [achievements.json](file:///workspace/achievements.json) 的 stats），Karma ∈ [-100, +100]。
- **业力增量直接复用现有指令分类**：强 C/B 改规则、`set_winner`、悔棋滥用 → 业力－；用 A2 机制而非改规则、惜败、克制 → 业力＋。→ 零新传感器，分类即信号。

**C2. 轮回路径（Samsara Path）**
- 一"世" = 一局。局终按业力决定下一世落到哪一道：
  - 高业力 → 升入"轻松"界（天界五子棋，AI=defensive、宽容）。
  - 低业力 → 堕入"残酷"界（地狱黑白棋，AI=aggressive + 开局即被 AI 改狠规则）。
- 6 个游戏从此连成一张救赎 / 堕落地图，而非 6 个孤立沙盒。

**C3. AI 跨局记忆（AI Memory）**
- 持久化 `ai_memory.json` = `{player_style, grudges[], gratitude[], past_personalities[]}`。
- 每局加载入 [mechanism_engine.py](file:///workspace/xiangqi/mechanism_engine.py) 的 `apply_personality_to_ai`：玩家总激进作弊 → AI 变"记仇"（defensive + value_biases 加权反制子）；温柔对弈 → AI"感恩"偶尔送子。
- 实现即给现有 `apply_personality_to_ai` 喂记忆派生的 overrides。

**C4. 判官判词 + 涅槃终局**
- 轮回转换时 AI 生成"判官判词"短叙事（复用 AI 生成能力）。
- 终极 meta 目标"涅槃"：需在六道间平衡业力达成 → 接入元成就系统。

**C5. 落地触点**
- [main.py hub](file:///workspace/main.py) 增 karma / memory API 与轮回调度；[mechanism_engine.py](file:///workspace/xiangqi/mechanism_engine.py) `apply_personality_to_ai` 增 memory overrides 入参（小改）；[ai_orchestrator.py](file:///workspace/xiangqi/ai_orchestrator.py) 分类时发 karma 事件 + `generate_verdict()`。
- 新增：`karma.json`、`ai_memory.json`、`samsara_state.json`；各游戏局终上报结果到 hub。

**灵活编码合规**：业力规则、判词叙事均 AI / 数据驱动；记忆是数据，应用是既有性格引擎；仅 karma / memory store 与轮回调度为薄基础设施硬编码。

## 四、优劣对比

| 维度 | A 可重玩核心循环 | B 社交 UGC 传播 | C 叙事情感深度 |
|-|-|-|-|
| 解决的核心问题 | 无限作弊=无聊（根本） | 缺传播 / 新鲜入口 | 主题空壳、无长期牵挂 |
| 与灵活编码契合 | 高（卡 = 自然语言指令） | 高（每日题 / 叙事 = AI 生成） | 高（业力 = 现有分类信号） |
| 落地复杂度 | 中高（run 状态 / 卡池 / 反制） | 中（hub 扩展 + 分享） | 中（跨游戏状态聚合） |
| 留存提升 | 极高（Roguelike 钩子） | 高（每日回归） | 高（情感 + 目标） |
| 获客 / 传播 | 中 | 极高（Wordle 楔子） | 中（故事分享） |
| 复用现有资产 | mechanism+personality+achievements | hub+token_stats+move_history | 六道 hub+personality+classification |

## 五、最终方案：三阶段递进（A 为骨架 / B 为引擎 / C 为灵魂）

**结论**：不做单选，而是**三阶段递进落地**——三者相互成就：

### Phase 1（核心骨架）= 方向 A「作弊契约 Roguelike」
先给沙盒一个可重玩循环，对冲"无限作弊 = 无聊"。契约卡即"预置作弊指令"，天然是 B 的每日题素材、C 的业力计费对象。

### Phase 2（增长引擎）= 方向 B「每日作弊挑战 + 棋谱剧场」
用 A 的契约卡构造每日题；用 Wordle 式分享卡做最锋利获客楔子；棋谱剧场把每局变可分享故事，二次传播。

### Phase 3（长期灵魂）= 方向 C「六道轮回业力 + AI 记忆」
业力系统为 A 的 Roguelike 提供"关卡 / 界"选择逻辑；把已建但空壳的六道主题兑现成叙事；AI 记忆让对手变角色，产生跨局牵挂。

**为何递进而非并行**：A 是"好不好玩"的根本，没有循环沙盒必死；B 是"怎么火"，但需 A 提供可分享的有趣内容；C 是"为什么长久玩"，需 A 的 run 结构承载轮回。三者依赖链清晰，分阶段降风险、控复杂度。

**灵活编码合规性总览**：三阶段中，契约卡 / 每日题 / 叙事 / 判词 / 业力规则全部是 JSON / AI 生成内容；仅薄基础设施（cheat_budget 计数、karma / memory store、轮回调度、计分 wrapper）硬编码——与现有机制引擎"原语硬编码 + 组合 AI 驱动"模式一致，不违背最高纲领。
