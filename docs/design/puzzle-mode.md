# 棋圣 · 解谜模式设计 (Puzzle Mode Design)

> **Baba is You 式规则重写解谜 × 棋圣灵活编码哲学**
>
> 把"棋圣 ChessSage"从自由对战平台改造为单机解谜游戏:给现有「灵活编码 / AI 作弊」机制套上一层**点数预算 + 多目标谜题**框架。
>
> 本文档为游戏创作者大赛作品的设计纲领,以趣味 / 创新 / 实验性为纲,不商业运营。

---

## 节 1 · 设计哲学与定位

### 1.1 一句话定位

**"规则本身是谜题,改写规则即是解题。"**

玩家不再是被动遵循规则的棋手,而是主动改写规则的"棋盘建筑师"。每一关都是一个被精心设计的规则困局,解法往往不是走出更精妙的棋步,而是找到那条"该被抽掉的规则线"。

### 1.2 三原则

1. **配置即真相 (Config is Truth)** — 棋盘的真相不在引擎代码里,而在 JSON 配置里。改配置 = 改世界。
2. **双解路并存 (Dual Paths)** — 每关都允许"纯棋艺硬解"与"AI 改写捷径"两条路,并存而非互斥。
3. **高手有奖 (Mastery Rewarded)** — 用 0 点纯棋艺解关的玩家获得三星与额外奖励,鼓励深度而非取巧。

### 1.3 与 Baba is You 的异同

| 维度 | Baba is You | 棋圣解谜模式 |
|---|---|---|
| 规则载体 | 棋盘上的字块(可推) | JSON 配置(用自然语言改) |
| 改写方式 | 物理推动字块组句 | 花 RP 雇 AI 生成 JSON Patch |
| 限制手段 | 字块布局本身 | RP 点数预算 |
| 高手奖励 | 无显式奖励 | 三星评级 + 成就 |
| 底层引擎 | 专设规则解释器 | 现有 jump/ray 原语 + 机制引擎 |

### 1.4 大赛导向

趣味 / 创新 / 实验性优先;可牺牲稳定性与性能;机制保持简明但具策略深度,不过度复杂化。

## 节 2 · 点数改写配额制 (Rewrite Budget · RP 引擎)

### 2.1 RP 定价表

每条 AI 指令按现有意图分类计费。RP (Rewrite Point) 是关卡内不可跨关累计的预算。

| 指令类型 | RP 消耗 | 设计理由 |
|---|---|---|
| **A1** 硬编码(直接判胜 / 悔棋) | **禁用** | 解谜模式引擎层硬拒,防绕过谜题核心张力 |
| **A2** 机制原语(冻结 / AI 接管 / 随机 / 额外回合 / 限步) | 3 / 个 | 组合性强,中等价位,鼓励机制组合解题 |
| **B** 棋盘变换(增删 / 移动 / 变型棋子) | 5 / 次 | 最粗暴,最贵,迫使玩家优先想规则巧解 |
| **C** 规则修改(改走法 / 吃子规则) | 2 / 字段 | 规则层巧解,便宜,主线工具 |
| **C+** 自定义棋子创建 | 4 / 个 | 创造性强,中高价位 |
| **D1** 界面 / 颜色修改 | **1 / 字段** | **最便宜** → 刻意引导涂色解法,服务灵活编码教学 |
| **D2** HTML 结构修改 | 6 / 区段 | 最贵,少用,边缘工具 |
| **E** 搞笑 | 0 | 不解题不扣点,纯娱乐 |

**定价逻辑**:
- D1 颜色修改最便宜(1 点) → 让"涂色关"的优雅解法天然浮现
- B 增删棋子最贵(5 点) → 阻止暴力摆棋,迫使玩家想规则层面的巧解
- C 改走法便宜(2 点) → 规则重写是 Baba-is-You 精神的主工具,定价亲民

### 2.2 双解路 + 三星评级

每关元数据三字段:

```json
{
  "budget": 5,                  // RP 上限
  "skill_solution": true,       // 是否存在纯棋艺零点解
  "skill_bonus": "achievement_id"  // 纯解奖励(成就 id,可为 null)
}
```

**评级规则**:

| 星级 | 条件 | 说明 |
|---|---|---|
| ★☆☆ | 用满预算(或 >50%)勉强过关 | 基础通关 |
| ★★☆ | 用 ≤50% 预算过关 | 低消耗解,所有关可达 |
| ★★★ | 用 0 点纯棋艺硬解 | 仅 `skill_solution=true` 关卡可达,高手专属 |

### 2.3 反作弊

解谜模式在引擎层硬拒会破坏谜题的指令:
- **A1 类**("我直接赢了""判我胜""悔棋到开局")→ 意图解析返回 F 类拒绝,提示"解谜模式禁用直接判胜"
- **越界修改** → Schema 校验拦截非本关允许的配置路径

胜利判定只认 `rules.json.objectives`,**不认** `board_state.game_status.state="ended"`。即:即便玩家绕过让 game_status 变 ended,只要 objectives 未达成,关卡不算通过。

### 2.4 存档与进度

- **每关固定预算,不累计**:防刷点,保证每关独立难度曲线
- **悟性点 (Insight)**:通关获得,用于解锁 meta 技能(如"预览 AI 修改结果""撤销免费一次""透视隐藏目标")
- **存档**:新建 `progress.json` 或扩展 `achievements.json`,记录每关三星 + 总悟性点

```json
// progress.json 示例
{
  "version": 1,
  "levels": {
    "manjie_manjianghong": {"stars": 3, "rp_used": 0, "completed_at": "..."},
    "tianjie_wuzidengke": {"stars": 2, "rp_used": 2, "completed_at": "..."}
  },
  "insight_points": 5,
  "unlocked_skills": ["preview_patch"]
}
```

## 节 3 · 多目标谜题库 (Objective Library)

### 3.1 目标类型库

把"胜负"泛化为可量化目标。每关一个主目标(+可选副目标)。最优解常是"让 AI 直接改配置",反向教育灵活编码哲学。

| 类型 | 编码 | 纯棋艺解(难) | AI 改写解(优雅 · 点数) |
|---|---|---|---|
| 覆盖率 | `coverage` | 走遍格子染色 | D1 改 board.json 区域上色(1 点) |
| 吃子数 | `captures` | N 步吃够 K 子 | 改 AI 性格为自送 / 加棋子 |
| 竞速 | `speedrun` | 最少步数达标 | 改 move_limits 多步 / 回合 |
| 撤离 | `evacuate` | 指定子走到出口 | 改该子走法为 region 瞬移 |
| 摆放 | `arrangement` | 移成目标阵型 | B 类直接摆放 |
| 颜色占比 | `color_ratio` | 走过染色 | D1 改 background_color |
| 残局解锁 | `endgame_unlock` | 正常破局 | 改一条规则打破僵局 |

### 3.2 rules.json.objectives 扩展结构

在现有 `win_conditions` 之外新增 `objectives` 字段(数据驱动,不破坏原有胜负逻辑):

```json
{
  "win_conditions": { "...原有..." },
  "objectives": {
    "primary": {
      "type": "coverage",
      "params": {"color": "red", "target_ratio": 0.6},
      "max_turns": 30,
      "display_name": "染红六成",
      "icon": "🟥"
    },
    "secondary": [
      {"type": "captures", "params": {"count": 3}, "optional": true, "display_name": "顺手吃三子"}
    ]
  },
  "puzzle_meta": {
    "budget": 5,
    "skill_solution": false,
    "skill_bonus": null,
    "mode": "puzzle"
  }
}
```

- `primary`:主目标,必须达成才算通关
- `secondary`:可选副目标,达成给额外悟性点
- `puzzle_meta.mode = "puzzle"`:引擎据此启用 RP 计费 + A1 硬拒 + objectives 判定

### 3.3 染色机制技术实现

**状态字段** — `board_state.json` 增 `painted_cells`:

```json
{
  "painted_cells": {
    "red": [[0,0],[1,0], ...],
    "blue": [[3,3], ...]
  }
}
```

**染色规则**:
- 每步落点格染当前方色
- 吃子格被对方覆盖(攻方色取代守方色)
- `board.json.regions` 可被 D1 直接染色 → 整片区域上色 = 1 点(涂色关的优雅解核心)

**判定** — `rule_engine` 增 `check_objective(board_state, objective)`:
- 每步走棋后调用
- 返回 `{achieved: bool, progress: float, detail: {...}}`
- 前端据 progress 实时显示进度条

## 节 4 · 三个示例关卡

### 关卡「满江红」(覆盖率 · 人界)

> **教"改配置比走棋高效千倍"**

| 字段 | 值 |
|---|---|
| 棋类 | 无限制象棋(xiangqi) |
| 目标 | 60% 格染成红色(`coverage`, target_ratio=0.6) |
| 预算 | 5 RP |
| skill_solution | false(纯棋艺几乎不可能) |
| 步数上限 | 30 |

**纯棋艺解**:控制车 / 马走遍 9×10 棋盘约需 50+ 步,远超 30 步上限。

**优雅解(1 点)**:玩家输入"把红方半边棋盘染红" → AI 走 D1 类,改 `board.json.regions.red_side` 上色 → 瞬间 50% 达标,再走几步补足至 60%。

**教学意图**:玩家第一次切身感受到"改配置比走棋高效千倍",这是灵活编码哲学的入门顿悟。

---

### 关卡「五子登科」(摆放 · 天界)

> **教"摆放类天然指向改写"**

| 字段 | 值 |
|---|---|
| 棋类 | 无限制五子棋(wuziqi) |
| 目标 | 5 个红子在棋盘中央排成十字(`arrangement`) |
| 预算 | 4 RP |
| skill_solution | true(极难,需精算五子棋走法) |
| 步数上限 | 20 |

**纯棋艺解(★★★)**:利用五子棋落子规则,精确计算 5 步落子位置排出十字。极难,需深度计算。

**优雅解(2 点)**:C 类改某棋子走法为 region 瞬移 → 走过去落子;或 B 直接摆放 5 子(5 点,超预算)→ 迫使玩家选规则改写而非暴力摆棋。

**教学意图**:摆放类目标天然指向 B/C 改写,玩家会主动发现"改走法比自己挪子高效"。

---

### 关卡「色即是空」(颜色占比 · 地狱界)

> **灵活编码哲学的最佳隐喻**

| 字段 | 值 |
|---|---|
| 棋类 | 无限制黑白棋(heibaiqi) |
| 目标 | 黑色区域占棋盘 70%(`color_ratio`, color=black, target_ratio=0.7) |
| 预算 | 3 RP |
| skill_solution | false |
| 步数上限 | 25 |

**纯棋艺解**:黑白棋翻转机制,逐格翻黑,慢且受对手干扰,25 步内难达 70%。

**优雅解(1 点)**:D1 改 `board.json.appearance.background_color` 为黑 + `regions` 涂黑大片区域 → 直接达 70%。

**教学意图**:题面诱导"翻转棋子"(传统棋艺思维),最优解却是"改棋盘颜色"(配置思维)。这是灵活编码哲学最凝练的隐喻 —— **当常规手段低效时,改写底层配置才是正解**。

## 节 5 · 关卡多样性指导

为满足"灵活多样"要求,关卡按四个正交维度交错设计:

### 5.1 按棋局形态

- **正常开局**:标准初始布局,目标改写规则达成
- **残局**:少子局面,聚焦少数棋子的精巧运用
- **特殊棋局**:自定义初始 board_state(如棋盘只剩一车一马、棋盘缩小为 5×5)

### 5.2 按目标类型

节 3.1 的七类目标交错使用,避免连续多关同类型疲劳。

### 5.3 按 RP 预算张力

- **0 预算关**(纯解关):只允许纯棋艺,测硬实力,给三星大奖
- **紧预算关**:预算 = 优雅解点数,容错极低,逼最优解
- **宽预算关**:预算富余,允许多种解法,教学关常用

### 5.4 按六道分章(复用现有叙事)

| 道 | 棋类 | 关卡主题方向 |
|---|---|---|
| 人界 | 象棋 | 残局解锁 / 覆盖率 |
| 天界 | 五子棋 | 摆放 / 连线计数 |
| 阿修罗 | 围棋 | 领地占比 / 撤离 |
| 畜生界 | 动物棋 | 撤离 / 吃子数 |
| 饿鬼界 | 跳棋 | 竞速 / 连跳计数 |
| 地狱界 | 黑白棋 | 颜色占比 / 翻转计数 |

## 节 6 · 扩展接口(预留 future 方向)

为头脑风暴剩余方向预留接入点,本次设计不实现,但目标类型与字段已为它们留好位置:

| Future 方向 | 接入方式 | 说明 |
|---|---|---|
| 方向 2 · 残局密码 | `endgame_unlock` 目标类型 | 破损残局逆向解谜,单点规则顿悟 |
| 方向 4 · 竞速撤离 | `speedrun` / `evacuate` 目标类型 | 时间压力 + 改写消耗回合 |
| 方向 5 · 规则考古 | 未来 `rule_archaeology` 目标类型 | 腐化规则修复演绎 |
| 方向 6 · 六道试炼 | 六道分章 + meta 进度 | 章节化叙事 + 原语解锁 |

这些方向可作为后续版本迭代内容,无需改动 RP 引擎与目标库骨架。

## 节 7 · 实现路线建议(大赛版最小闭环)

本文档为设计纲领,不包含代码。后续实现按以下优先级推进:

| 优先级 | 工作项 | 涉及文件 |
|---|---|---|
| **P0** | RP 计费钩子 + A1 硬拒 | `mechanism_engine.py` / `ai_orchestrator.py` |
| **P0** | rules.json.objectives 扩展 + `check_objective()` | `rules.json` / `rule_engine.py` |
| **P1** | board_state.painted_cells + 染色逻辑 | `board_state.json` / `rule_engine.py` |
| **P1** | progress.json 存档 + 三星评级 | 新建 `progress.json` / `main.py` |
| **P2** | 3 个示例关卡数据 | 各棋类 `configs/` |
| **P3** | meta 技能系统(悟性点解锁) | `main.py` / 前端 |

**最小可玩闭环 = P0 + P1 + 3 关卡数据**:玩家能进入解谜关 → 花 RP 改配置 → 染色 / 摆放 / 涂色 → 达成目标 → 三星结算。这一闭环已足以体现"灵活编码解谜"的核心创新。
