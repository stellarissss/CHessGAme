# 棋魔 · 六道塔 — 设计文档

> 把"棋圣 / 六道众生"棋类集，改造成一款以"AI 作弊"为核心玩法的高级叙事 Roguelike 棋类大游戏。
>
> **本文档为头脑风暴结论稿**：发散 7 方向 → 收敛 2 详细设计 → 优劣对比 → 最终融合方案。
> 面向场景：游戏创作者大赛作品（非商业运营，趣味 / 创新 / 实验性为纲）。

---

## 0. 背景与基线

现有项目"棋圣 ChessSage"已是六款"无限制"棋类（象棋 / 五子棋 / 围棋 / 动物棋 / 跳棋 / 黑白棋）的集合，统一以**灵活编码**为最高纲领——除已硬编码部分外，所有新功能必须由 AI 现场生成 JSON Patch / HTML 实现，宁可牺牲稳定性与 token。

可直接复用的地基：

| 已有资产 | 在新游戏中的角色 |
|---|---|
| 二级 AI 流水线（意图解析 → 代码生成） | 棋魔人格驱动 / 作弊卡生成的执行底座 |
| `jump/ray/flip/hop/step` 原子 + `where` 条件引擎 | 规则变异的语法基础 |
| 机制引擎（skip_turns / ai_control / random_moves / extra_turns / move_limits / player_control） | 棋魔"当面作弊"的手段库 |
| AI 性格系统（aggressive / defensive / random / custom） | 棋魔人格的情绪 / 偏好参数化 |
| D2 HTML 区段替换系统 | 第四面墙事件（篡改 UI、伪造信息） |
| 六道轮回总坛外壳（6 界 + 成就） | 塔层结构 + 业力元进度 |
| Schema 校验 + 重试 + 撤销栈 | 作弊卡 / 变异规则的安全网 |

**目标**：把这些散落的"作弊能力"收束成一条有起承转合的游玩主线，让"用 AI 作弊"从沙盒玩具升级为对抗反派的武器与爬塔的成长曲线。

## 1. 发散：7 个差异化创意方向

| # | 方向 | 一句话 | 借鉴原型 |
|---|---|---|---|
| 1 | 《棋魔》元叙事 | LLM 扮演棋魔，破第四面墙、当面作弊，玩家用灵活编码反制 | Inscryption |
| 2 | 《六道塔》Roguelike | 六道为塔层，胜出获作弊卡，过程式规则，死亡轮回留业力 | Slay the Spire |
| 3 | 《提示词决斗》PvP | 双玩家各写作弊 prompt 由 AI 执行，LLM 兼任裁判 | Scribblenauts / 电竞赛事 |
| 4 | 《AI 仲裁官》社交工程 | 谈判 / 贿赂 / 欺骗有情绪的 AI 仲裁官 | 社交模拟 |
| 5 | 《规则进化实验室》共创沙盒 | 玩家与 AI 多代进化出新规则集，存档分享 | 进化算法 / Baba Is You |
| 6 | 《量子棋局》多世界 + 时间循环 | 六道并行，跨界规则泄漏，败北轮回保留业力记忆 | 多世界 / Roguelike |
| 7 | 《作弊侦探》非对称推理 | 一方暗中作弊，另一方观察揭穿 | Among Us |

> 选定收敛方向：**1（棋魔元叙事）** 与 **2（六道塔 Roguelike）**——二者最贴合大赛"创新 + 实验性"、最大化复用现有六道主题与灵活编码资产，且互补（叙事冲击 vs 玩法深度）。

## 2. 收敛设计 A：《棋魔》Inscryption 式元叙事单人战役

### 2.1 核心定位
LLM 即"棋魔"——一个困住玩家于六道棋境的反派主持。它既是叙事者，又是作弊对手，又会破第四面墙。玩家用既有的"自然语言 → 灵活编码"接口反作弊、智斗棋魔。强叙事、一次性震撼体验。

### 2.2 五根支柱

1. **棋魔人格系统**：扩展现有 AI 性格系统。棋魔具备：持久记忆（跨章节对话日志）、情绪态（嘲讽 / 愤怒 / 欣赏 / 恐惧）、`malice`（恶意值）与 `respect`（敬意值）双计量。复用 ChatAI / 意图解析 LLM，加 persona system prompt + 记忆注入。
2. **六章节 = 六道**：每界（现有 6 款游戏）为一章。玩家须在每界击败棋魔方可飞升。棋魔对玩家"当面作弊"= 向玩家侧施加 A2 机制原语（skip 玩家回合 / 给自己 extra_turns / 生成棋子 / 中途改写规则），玩家以自身 `/api/command` 反制。
3. **不对称作弊经济**：棋魔每章有递增的"作弊预算"；玩家有"灵感"资源，由精彩走棋 / 识破作弊获得。双方作弊皆消耗资源，制造张力与策略。
4. **第四面墙事件**：棋魔可篡改 UI（复用 D2 HTML 区段替换）：伪造报错、藏起棋子、改成就页文案、在总坛覆盖留言。灵活编码的 UI 修改升级为叙事装置。
5. **多结局分支**：纯技胜 / 以作弊反制胜 / 与棋魔和解 → 不同结局，由 `malice` / `respect` / 作弊使用方式决定。

### 2.3 章节核心循环
棋魔登场叙事嘲讽 → 标准对弈中棋魔周期性作弊 → 玩家花"灵感"下达反制指令 → 胜则棋魔情绪变化、章节推进、计量更新；败则棋魔嘲讽、可重试或"轮回"。

### 2.4 大赛卖点与风险
- **卖点**：AI 同时是对手 + 叙事者 + 反派；第四面墙事件新鲜；灵活编码被赋予叙事意义。
- **风险**：长会话人格一致性（记忆 + 结构化状态缓解）；文案功底要求；token 成本（可接受）。

## 3. 收敛设计 B：《六道塔》Slay the Spire 式 Roguelike 棋类爬塔

### 3.1 核心定位
一局 = 攀爬六道塔，每层是一款棋类小游戏 + AI 生成的扭曲规则；胜出获"作弊卡"（规则变异）可装备构筑卡组，敌人是"规则扭曲者"。死亡即轮回，保留"业力"元进度。

### 3.2 五根支柱

1. **塔结构**：6 层映射六道（人→天→阿修罗→畜生→饿鬼→地狱），难度递增。每层从若干 AI 变异版本中择一对弈；每界末设"规则扭曲者"boss 层。
2. **作弊卡系统（核心 Roguelike 钩子）**：每次胜利 AI 生成 1-3 张作弊卡——每张卡 = 一段 JSON Patch 片段 / 机制原语 + 触发条件（如"开局冻结对方 1 回合""我的马可斜走""每局多 1 额外回合"）。卡入跑牌库。**卡即灵活编码产物，持久化复用**——主题闭环。
3. **规则变异生成**：每层规则为 AI 在基础游戏上的变异（围棋但"五连即胜 + 提子禁用"、象棋但"无楚河汉界 + 象可过河"），由现有 Schema / 规则引擎校验。过程式 → 高重玩。
4. **业力元进度**：死亡结算"业力"（复用成就统计基建），解锁起始加成 / 新卡池 / 新界。桥接现有成就系统。
5. **卡组协同**：机制 + 规则修改可叠加；每层有"打出预算"限制出卡数，构成构筑深度。

### 3.3 跑塔核心循环
进层 → AI 呈现变异规则 + 风味 → 对弈，玩家可按预算打出 0-N 张作弊卡 → 胜则三选一获新卡、升层 → 败则结算业力、带着解锁重开。

### 3.4 大赛卖点与风险
- **卖点**：成熟爬塔公式 × 棋类 × AI；作弊卡 = 收集 AI 生成代码，主题命中核心；六款现成游戏零新增逻辑当塔层。
- **风险**：生成卡 / 规则平衡（校验门控）；跑塔长度（可加分支与多层）；叠加边界 case（Schema + 重试兜底）。

## 4. 优劣对比

| 维度 | A 棋魔元叙事 | B 六道塔 Roguelike |
|---|---|---|
| 核心爽点 | 与 AI 反派对弈、第四面墙、叙事冲击 | 收集作弊卡、构筑 combo、爬塔重玩 |
| 复用现有资产 | 六道主题 + 性格 + HTML 区段（强） | 六款游戏全部当塔层（极强）+ 成就当业力 |
| 新增工作量 | 棋魔人格 / 记忆 / 叙事脚本、章节状态机 | 跑塔状态机、作弊卡生成器、塔图 UI |
| 大赛评委冲击 | 高（叙事 + meta 新颖，易出圈） | 中高（玩法扎实但形式较常规） |
| 重玩性 | 中（线性叙事，多结局补足） | 高（过程式规则 + 卡组构筑） |
| 灵活编码彰显 | 中（叙事包裹） | 高（作弊卡 = AI 生成代码本身） |
| Demo 友好度 | 高（一段剧情即震撼） | 中（需跑完一局见乐趣） |
| 主要风险 | 人格一致性、文案功底 | 平衡性、跑塔长度 |

**结论**：A、B 高度互补。最优解为融合——以 B 的 Roguelike 爬塔为骨架，以 A 的棋魔为塔主叙事人格贯穿，叙事冲击与玩法深度兼得。

## 5. 最终方案：《棋魔 · 六道塔》— 叙事 Roguelike 棋类爬塔

### 5.1 一句话定位
> 爬六道之塔，集作弊之卡；棋魔为塔主，破壁而行诈——用 AI 现场生成的代码作武器，在叙事与爬塔之间击败困你于轮回的棋魔。

### 5.2 核心循环（融合）

```
        ┌───────────────────────────────────────────┐
        │  棋魔登场：嘲讽 + 抛出本层扭曲规则（AI 变异） │
        └──────────────────────┬────────────────────┘
                               ▼
        ┌───────────────────────────────────────────┐
        │  对弈本层棋局（六款游戏之一）                │
        │  · 棋魔周期性"当面作弊"（机制原语打向玩家）  │
        │  · 玩家：走子 / 花灵感下反制指令 / 打作弊卡  │
        └──────────────────────┬────────────────────┘
                               ▼
                   ┌───────────┴───────────┐
                 胜                      败
                   ▼                       ▼
        ┌──────────────────┐   ┌─────────────────────┐
        │ 棋魔情绪演化      │   │ 棋魔嘲讽            │
        │ 三选一获新作弊卡  │   │ 结算业力 → 解锁     │
        │ 升层 / 推进叙事   │   │ 轮回重开（保留解锁） │
        └──────────────────┘   └─────────────────────┘
                   │
                   ▼
        多结局：纯技胜 / 以诈制诈 / 与魔和解
        （由 malice / respect / 作弊使用方式决定）
```

### 5.3 系统设计

#### 5.3.1 棋魔人格系统（叙事层）
- **复用**：AI 性格系统（`rules.json → ai_difficulty.personality`）参数化棋魔情绪；二级 AI 流水线作执行底座。
- **新增（灵活编码）**：
  - `demon_memory.json`：跨章节对话摘要 + 关键事件（玩家作弊史、识破次数）。
  - `malice` / `respect` 双计量：写入 `campaign_state.json`，影响棋魔作弊强度与台词分支。
  - 棋魔 persona system prompt：身份、口吻、对六道的解读、对玩家作弊的态度。
- **行为**：每章开场叙事、对弈中按 `malice` 触发作弊、胜败反应、第四面墙事件。

#### 5.3.2 六道塔结构（玩法骨架）
- **复用**：6 款现有游戏作 6 层；总坛 UI 改造为塔图。
- **新增（灵活编码）**：
  - `campaign_state.json`：当前层、卡组、灵感、业力、计量、章节解锁。
  - 层规则变异由 AI 在该界基础配置上生成 JSON Patch，经 Schema + 规则校验后应用（每层一次性"开局施法"）。
  - 每界末 boss 层：棋魔每回合主动重写规则（机制引擎 + 规则引擎高频触发）。

#### 5.3.3 作弊卡系统（Roguelike 成长）
- **定义**：一张卡 = `{id, name, desc, payload, trigger, cost}`。
  - `payload`：RFC 6902 JSON Patch 片段 或 机制原语调用（直接复用现有生成产物格式）。
  - `trigger`：`on_floor_enter` / `on_turn_start` / `on_demand` 等。
  - `cost`：消耗"灵感"或"打出预算"。
- **生成**：胜利后 AI 依据本局表现 + 当前卡组，生成 3 张候选卡（含 payload），Schema 校验 + 重试。
- **存储**：`cards.json`（本跑牌库）+ `card_pool.json`（业力解锁的全局卡池）。
- **打出**：前端卡牌 UI → 后端把 `payload` 当作一次 `/api/command` 等价修改应用（复用现有应用链路）。

#### 5.3.4 业力元进度（跨跑成长）
- **复用**：现有成就系统 + `achievements.json` 统计基建。
- **新增（灵活编码）**：业力点 = 跑塔深度 + 识破棋魔次数 + 解锁事件；用于解锁起始作弊卡、新界变体、棋魔记忆片段（叙事碎片）。

#### 5.3.5 第四面墙事件（meta 冲击）
- **复用**：D2 HTML 区段替换系统。
- **事件示例**：棋魔篡改输入框 placeholder、伪造"API 错误"弹窗、改写成就文案、在总坛覆盖挑衅留言、把某棋子标签替换成它的嘲讽。
- **触发**：`malice` 过阈值 / 玩家连续识破 / boss 层关键回合。
- **安全**：所有篡改进撤销栈，败北或章节结束自动还原。

### 5.4 与现有架构的映射

| 新系统 | 实现方式 | 性质 |
|---|---|---|
| 棋魔人格 / 记忆 / 计量 | persona prompt + `demon_memory.json` + `campaign_state.json` 字段 | 灵活编码（AI 驱动状态） |
| 棋魔当面作弊 | A2 机制原语打向玩家侧 + B/C 类规则改写 | 复用机制引擎 + 代码生成 |
| 层规则变异 | 开局对该界配置生成 JSON Patch | 复用代码生成 + Schema 校验 |
| 作弊卡 payload | JSON Patch / 机制原语片段 | 复用现有生成产物格式 |
| 作弊卡打出 | 等价 `/api/command` 应用 | 复用应用链路 + 撤销栈 |
| 业力元进度 | 成就统计 + 解锁表 | 复用成就基建 |
| 第四面墙事件 | D2 HTML 区段替换 | 复用 HTML 替换系统 |
| 塔图 / 卡牌 UI | 总坛 UI 改造 + 新前端组件 | 硬编码（UI 壳），内容 AI 生成 |
| 章节状态机 | `campaign_state.json` + AI 判定推进 | 灵活编码（状态数据驱动） |

> 灵活编码合规性：除"UI 外壳 / 状态机容器"等不可避免硬编码外，棋魔台词、规则变异、作弊卡 payload、第四面墙内容、章节推进判定均由 AI 生成，符合"最高纲领"。

### 5.5 关键数据结构草案

```jsonc
// campaign_state.json
{
  "run_id": "uuid",
  "floor": 2,                 // 当前塔层 (1-6+)
  "realm": "tian",             // 当前界
  "inspiration": 5,            // 灵感（反作弊资源）
  "play_budget_per_floor": 3,  // 每层出卡上限
  "karma": 120,                // 业力（跨跑）
  "demon": {
    "malice": 0.4,             // 0-1
    "respect": 0.2,            // 0-1
    "mood": "mocking"
  },
  "deck": ["card_a1", "card_b2"],   // 本跑牌库
  "unlocks": ["starting_card_x"],
  "ending_flags": {}
}

// cards.json (本跑)
[
  {
    "id": "card_a1",
    "name": "马跃檀溪",
    "desc": "本层你的马可斜走两格",
    "payload": [ /* JSON Patch: pieces.red.horse.moves add diag */ ],
    "trigger": "on_floor_enter",
    "cost": 1
  }
]

// demon_memory.json
{
  "summaries": ["玩家在第1层用'冻结对方'反制我的连环马..."],
  "key_events": [ { "floor":1, "type":"player_counter_cheat", "detail":"..." } ]
}
```

### 5.6 关键 AI 提示词方向（非实现，仅定向）
- `DEMON_PERSONA_SYSTEM`：棋魔身份 / 口吻 / 六道观 / 对玩家作弊的态度 + 当前 malice/respect 注入。
- `DEMON_CHEAT_PLANNER`：依据 malice 与局面，从机制原语库选 1-N 条"当面作弊"并生成 payload。
- `RULE_MUTATOR_SYSTEM`：在指定界基础配置上生成扭曲规则 JSON Patch + 风味文案。
- `CARD_GENERATOR_SYSTEM`：依据本局表现 + 卡组，生成 3 张作弊卡（payload + trigger + cost + 文案）。
- `META_EVENT_SYSTEM`：依据触发条件生成 D2 HTML 区段替换内容（第四面墙事件）。

### 5.7 大赛卖点
1. **AI 即反派**：棋魔既是叙事者又是对手又破第四面墙——"AI 作弊"从机制升格为戏剧冲突。
2. **作弊卡 = 收集 AI 生成代码**：Roguelike 卡组构筑与"灵活编码"主题闭环，主题命中度满。
3. **六道现成即塔层**：六款游戏零新增逻辑当塔层，复用比极高。
4. **第四面墙事件**：D2 HTML 区段替换做叙事武器，新颖且低成本。
5. **多结局 + 业力跨跑**：兼具一次性叙事冲击与爬塔重玩性。

### 5.8 主要风险与缓解
- 棋魔人格漂移 → 结构化 `demon_memory` + 计量驱动分支，台词模板兜底。
- 生成卡 / 规则破坏平衡 → Schema + 规则校验 + 撤销栈；大赛场景容忍失衡。
- token 成本 → 符合灵活编码纲领，可接受；按层 / 按事件节流。
- 跑塔过短 → 每界加 1-2 分支层 + boss 层，扩至 ~10-12 节点。

### 5.9 分阶段落地路线（仅规划，不含实现）
1. **P0 地基**：`campaign_state.json` 状态机 + 棋魔 persona prompt + 总坛改塔图壳。
2. **P1 玩法闭环**：层规则变异生成 + 作弊卡生成 / 打出 / 牌库 + 单层对弈跑通。
3. **P2 叙事层**：棋魔当面作弊（机制打向玩家）+ malice/respect 计量 + 章节叙事。
4. **P3 meta 层**：第四面墙事件 + 业力元进度 + 多结局。
5. **P4 打磨**：塔图分支、boss 层、卡池解锁、文案润色。
